PART 01 · 检测器解剖

任何检测器，都是三段式

特征提取 → 多尺度融合 → 预测头。近三年所有新工作，改的都是这两三段里的某一处。

为什么值得先看这张图

  • Backbone：决定特征质量上限，R50 → Swin → VMamba / TransNeXt / DINOv3
  • Neck：决定多尺度信息怎么融合，FPN / PAN / CCFM 三代演进
  • Head：决定输出形式，anchor-based 与 anchor-free 两条分水岭
  • 训练侧与推理侧要目标一致——这是 YOLOv10 与 DETR 共同的底层主张

读论文时先把这张图摆出来，问自己三个问题： 这篇论文动的是哪一段？是训练侧还是推理侧？ 几乎所有检测论文都能被塞进这个框架里。

三条路线，正在互相吸收

  • 两阶段：精度上限高、小目标强，但流程长、推理慢
  • 一阶段：端到端训练、速度快、易部署，早期正负样本失衡
  • 端到端 DETR：无 NMS、无锚框、架构统一，但早期收敛慢
  • 趋势：两阶段被「一阶段 + 更好的样本分配」逼近，一阶段被「端到端」改造

写综述时，这张表是最好用的骨架：按路线分类，而不是按年份罗列， 读者才能一眼看出每个方向还缺什么。

PART 02 · 核心原理

DETR 端到端检测：训练与推理原理

把检测变成「集合预测」：一对一匹配替代 NMS，用匈牙利算法求全局最优。 这张图是后面所有 DETR 系论文的地基。

① 匈牙利匹配：把「分配」变成优化问题

构造 N×M 代价矩阵（分类损失 + L1 + GIoU），用匈牙利算法求全局最优排列，而不是传统检测那样按 IoU 贪心阈值分配候选框。每个 GT 只被 1 个 Query 匹配，其余 Query 全部记为无目标——这就是「无冗余框」的来源。

② 去噪训练 CDN：所有 DETR 系提速的共同前提

给 GT 框加随机噪声，把这些「带噪框」当成额外正样本 Query 一起送进 Decoder。模型只要学会「去噪还原」，收敛速度就能提升数倍——DETR 原本需要 500 epoch 才能训好，加了去噪之后 12 epoch 就够。

③ 两条改进轴：匹配方式 与 回归形式

DEIM 改的是匹配（密集一对一 → 更快收敛），D-FINE 改的是回归（L1 单点 → 细粒度分布细化 → 更准定位）。两件事在数学上彼此正交，因此可以叠加——这正是写文章时最顺的一条叙事线。

01

端到端 DETR 系

集合预测 · 匹配机制 · 回归形式
端到端路线把检测从「先出候选再筛选」改写成「直接预测一个集合」。这条线的三年进展几乎全部集中在两处：预测与 GT 怎么配对（匈牙利匹配 → 密集一对一 → 图协作），以及框怎么回归（L1 单点 → 细粒度分布细化）。这两件事彼此正交，因此可以叠加——这正是写文章时最好讲的叙事结构。
ICLR 2023 端到端 DETR 系 奠基前置

DINO: DETR with Improved DeNoising Anchor Boxes for End-to-End Object Detection

DINO：带改进去噪锚框的端到端目标检测 DETR
arXiv:2203.03605 · 2022-03-07 · Hao Zhang、Feng Li、Shilong Liu 等 8 人
核心思想把 DETR 的集合预测与去噪训练结合——给 GT 框加噪构造额外的正样本 Query，让 Decoder 同时学习「去噪还原」，把收敛所需的 500 epoch 压到 12 epoch。
创新点
  • 引入对比去噪 CDN：给 GT 框加随机噪声，生成额外正样本 Query
  • 混合查询选择：把编码器的内容特征与位置锚点拼接起来选初始 Query
  • Look-Forward-Twice：在分支之间传递梯度，稳定深层监督
  • 解码器额外精修层：逐层提升框的定位精度
📊 COCO AP 42.3 → 49.0（ResNet-50，12 epoch）
✍️ 凡是要写「DETR 收敛慢」或「去噪训练」，这一篇是必引的前置工作，也是 DEIM / D-FINE 等后续改进的共同前提。

DETRs with Collaborative Hybrid Assignments Training

协同混合分配训练的 DETR（Co-DETR）
arXiv:2211.12860 · 2022-11-22 · Zhuofan Zong、Guanglu Song、Yu Liu
核心思想指出 DETR 的「一对一匹配」导致正样本过于稀疏，改为在多个辅助检测头上做混合分配（一对一 + 一对多）协同训练，最后只保留主头的输出做推理。
创新点

  • 正样本集合在辅助头之间共享，互相「借」监督信号

✍️ 讨论「正样本稀疏」「一对一匹配的信息瓶颈」时引用；与 DEIM 的 Dense O2O 是同期但独立的两种解法。

D-FINE: Redefine Regression Task in DETRs as Fine-grained Distribution Refinement

D-FINE：把 DETR 的回归任务重新定义为细粒度分布细化
arXiv:2410.13842 · 2024-10-17 · Yansong Peng、Hebei Li、Peixi Wu 等 6 人
核心思想认为 L1 回归是 DETR 定位精度的瓶颈，于是把回归从「预测一个坐标」改成「预测一个以真值为中心的离散分布」，再对分布做细化，把定位精度整体抬高一个档次。
创新点
  • FDR 细粒度分布细化：预测离散分布而非单点坐标
  • GDR 全局分布细化：借高层特征迭代优化整层分布
  • 分布式回归天然编码了定位不确定性
  • 可直接叠加到 DINO / DEIM 等已有框架上
📊 COCO ResNet-50 AP 54.3；12 epoch 训练即超越此前最好结果
✍️ 讨论「回归形式」「定位精度瓶颈」时引用；与 DEIM 的匹配改进构成两条正交的技术线。

DEIM: DETR with Improved Matching for Fast Convergence

DEIM：用改进的匹配实现快速收敛的 DETR
arXiv:2412.04234 · 2024-12-05 · Shihua Huang、Zhichao Lu、Xiaodong Cun 等 6 人
核心思想指出密集一对一匹配能提供更丰富的正样本监督，从而在同样的 12 epoch 内比 DINO 收敛得更快；同时用匹配性感知损失抑制低质量匹配对训练的干扰。
创新点
  • Dense O2O 密集一对一匹配：每个 GT 取 Top-K 个高重叠 Query

arXiv:2609.26092 · 2026-08-06 · Wenxiao Fan、Jingling Fu、Luohang Liu 等 11 人
核心思想指出 O2O 匹配下，一个目标的最佳分类、中心、尺度与重叠证据往往分散在多个 query 上，只有被匹配的「属主」拿到正监督——作者称之为「query 知识碎片化」；BS-O2G 用稀疏的预测感知图组织 query 协作，同时完整保留原 O2O 匹配器、正标签与目标函数。

Dynamic Query as Budgeting for Tiny Object Detection

Dynamic Query as Budgeting：把小目标检测的动态查询重述为「预算分配」
arXiv:2610.33430 · 2026-10-24 · Yi Zhang、Di Xiong、Ge Gao 等 7 人
核心思想指出 DETR 系小目标检测器的动态查询机制把两件事纠缠在一起——解多少个 query、以及选哪些 query；实验证明动态查询的主要作用是「预算分配」（按目标密度分配解码容量），而非精细的查询选择。

02

实时检测

把速度与精度同时往前推一格
实时线的核心矛盾是「训练与推理不一致」和「后处理开销」这两个历史包袱。YOLOv9 用可编程梯度信息解决深层监督失效，YOLOv10 用一致性双重标签分配彻底去掉 NMS，YOLOv12 把注意力做便宜；RT-DETR 则从 DETR 一侧证明端到端也能实时。三条路径互补而非互斥，是可以并排写进一张对比表的。

YOLOv10: Real-Time End-to-End Object Detection

arXiv:2405.14458 · 2024-05-23 · Ao Wang、Hui Chen、Lihao Liu 等 7 人

YOLOv12: Attention-Centric Real-Time Object Detectors

YOLOv12：以注意力为中心的实时目标检测器
arXiv:2502.12524 · 2025-02-18 · Yunjie Tian、Qixiang Ye、David Doermann

TransNeXt 用聚合邻域注意力刻画注视点聚集特性，VMamba 用状态空间模型以线性复杂度换取全局感受野，VGTok 则把「固定 token 网格」改成「按区域变粒度」。骨干侧的变化常常比检测头更直接地影响小目标与密集目标的表现，也是课程实验里最容易做出可复现消融的一环。

TransNeXt: Robust Foveal Visual Perception for Vision Transformers

TransNeXt：鲁棒的注视点式视觉感知 Transformer
arXiv:2311.17132 · 2023-11-28 · Dai Shi
核心思想提出聚合邻域注意力——在局部窗口内把 query 与其邻近 key/value 一并聚合，用连续位置偏置与可学习半径刻画人类注视点的聚集特性，兼顾线性复杂度与密集目标表现。
创新点
  • 聚合邻域注意力（Aggregated Neighborhood Attention）
  • 连续位置偏置建模跨窗口的相对位置关系
  • 可学习聚合半径，自适应分配注意力范围
  • 分类 / 检测 / 分割三任务通用骨干
📊 COCO 检测 AP 51.8 量级，同参数量下优于 ConvNeXt 与 Swin
✍️ 讨论「注意力骨干 vs 卷积骨干」时的近期代表；也适合作为「换骨干做消融」的实验素材。

VMamba: Visual State Space Model

VMamba：视觉状态空间模型
arXiv:2401.10166 · 2024-01-18 · Yue Liu、Yunjie Tian、Yuzhong Zhao 等 9 人
核心思想把状态空间模型（SSM）引入视觉骨干，用选择性扫描沿四个方向在图像上做线性复杂度建模，以卷积级别的速度获得全局感受野，替代自注意力的平方复杂度。
创新点
  • 视觉 SSM 骨干 + 跨方向扫描的二维状态空间建模
  • 选择性扫描机制，按输入内容自适应决定保留或丢弃信息
  • 与 CNN 同为线性复杂度，可扩展到高分辨率输入
  • VSSM 系列即插即用，可直接替换 DETR / YOLO 的骨干
📊 吞吐与卷积相当；检测 / 分割上优于同规模 ViT 与 Swin
✍️ 谈小目标、高分辨率任务的骨干选择，或介绍 SSM 视觉化时引用；「视觉 Mamba」这一支的代表作。

Variable-Granularity Tokenization for High-Resolution Object Detection

VGTok：面向高分辨率目标检测的可变粒度 Tokenization
arXiv:2608.28706 · 2026-08-27 · Khayrul Islam
核心思想ViT 检测器在进入任何学习模块之前就固定了统一的 token 网格，原生分辨率的航拍检测器只能在「解析几像素目标」与「守住算力显存上限」之间二选一；VGTok 是一个免训练 tokenizer，在编码之前按区域从像素出发设定 patch 粒度。
创新点
  • 以多尺度形态学 top-hat 可分性为每个区域打分，按每图像分位数阈值锁定 token 预算
  • 结构张量门控（λ_min）：只在二维目标结构成立处细化，一维杂乱保持粗粒度
  • 产出的 token 集合是图像的严格划分，无重复无遗漏
  • 训练无关，可作为冻结 checkpoint 的即插即用模块
📊 Co-DETR + EVA-02 ViT-L 在 VisDrone-val 上 40% token 预算即达 44.22 AP，密集设定 48.38 AP（较最强已发表结果 +6.08）；AI-TOD-v2 达 37.27 AP
✍️ 讨论「高分辨率 / 密集小目标」与「token 预算」时引用；把「分辨率—算力矛盾」换了个问法，值得借鉴。

PART 04 · 难点专题

小目标检测：一个还没被解决干净的矛盾

目标小于 32×32 像素时，检测器丢掉的不只是细节，还有「位置先验」。 这是一个适合持续发论文的议题。

🔍 为什么小目标还是热点

它不是一个「调参问题」，而是特征分辨率与语义粒度的根本矛盾：提高分辨率会显著增加计算量，语义太弱又无法可靠分类。这个矛盾至今没有被彻底解决，因此每一年都有新论文。

📐 四条解法主线

特征融合（FPN / PAN 自顶向下）· 提高分辨率（SAHI 切片推理、TTA）· 位置先验（anchor-free + 可学习位置编码）· 注意力（Swin / VMamba 层次化注意力、专用小目标头）。

✍️ 写论文的注意事项

单报 AP 一定会被质疑。必须同时给出 AP_s（小目标）与推理速度，并在 VisDrone / AI-TOD / UAVDT 上验证——否则审稿人会认为你没有真正解决小目标。

PART 06 · 动手做

复现实验路线：4 个实验，从零到发论文

这四个实验按顺序做完，学生能独立复现近三年的代表性工作；老师能直接在此基础上派生自己的论文。

LAB 01 · 基础

把检测器拆开看：复现 Faster R-CNN 与 YOLOv8

先用最朴素的两条路线跑通，理解「候选框 → 分类回归」与「密集预测」的差别。

  • COCO val2017 子集，ResNet-50 骨干
  • 记录 AP / AP50 / AP75 / 参数量 / 单图延迟
  • 对比 anchor-based 与 anchor-free 的正负样本分配差异
产出：一张基础性能对照表 + 一份 loss 曲线分析
LAB 02 · 端到端

复现 DINO，并把它训到 12 epoch

理解集合预测、匈牙利匹配与去噪训练这三件事，是 DETR 系所有后续工作的前提。

  • 实现简化的二分图匹配（scipy linear_sum_assignment）
  • 实现 CDN 去噪训练，观察收敛速度的差异
  • 记录 12 / 50 / 300 epoch 各自的 AP 曲线
产出：去噪训练前后的收敛速度对比图（可直接进论文）
LAB 03 · 改进

在 DINO 上叠加 DEIM 与 D-FINE

验证「匹配机制」与「回归形式」两条改进轴可以独立叠加——这是最好讲的一个故事。

  • 把一对一匹配改成 Dense O2O（每个 GT 取 Top-K）
  • 把 L1 回归换成细粒度分布细化（FDR）
  • 做 2×2 消融：DINO / +DEIM / +D-FINE / 两者都加
产出：2×2 消融表，直接支撑「两条线正交」的论点
LAB 04 · 小目标

小目标专项：SAHI 切片 + AP_s 评测

把前面的模型放到无人机小目标场景上，顺带摸清这个方向的真实痛点。

  • 在 VisDrone / AI-TOD-v2 上评测 AP_s 与 AP50
  • 实现 SAHI 切片推理，比较切块尺寸对 AP_s 的影响
  • 分析失败案例：密集遮挡、极小目标、背景干扰
产出：小目标失败模式分析，为选题提供依据
PART 07 · 科研选题

科研选题建议：6 个可直接开题的方向

按「投入产出比」排序。难度标签：🟢 硕士一年级可做 · 🟡 需要一定工程积累 · 🔴 需要算力或新数据。

🟢 难度低

DETR 系的「正样本数量」消融：匹配机制到底在做什么

DEIM 主张密集一对一匹配带来更快的收敛，BUTR（arXiv:2610.33430）则用实验指出 动态查询的主要作用其实是预算分配而非精细选择——这两个结论未必矛盾。 系统地做一组「匹配策略 × query 预算」的二维消融，是一个工作量可控但结论有价值的题目。

数据集：COCO + CrowdHuman（密集场景）· 算力：单卡 A10 即可
🟢 难度低

骨干替换的系统性消融：ConvNet / Swin / SSM / 变粒度 token

把 ConvNeXt、Swin、VMamba、TransNeXt、VGTok 统一接到同一个 DETR 框架下， 在小目标与密集目标上做横向对比。 「特征质量 → 检测性能」的传导路径目前缺少系统结论，是一篇扎实的短文。

数据集：COCO + VisDrone · 算力：单卡 A10 即可
🟡 难度中

开放词汇 × 小目标的交叉空白

FocusOVD（arXiv:2610.27479）只做了 2026 年 10 月这一篇，说明这个交叉方向还很空。 开放词汇方法普遍在 COCO-OVD 上刷分，但很少认真报告 AP_s 与长尾小类别。 补上这一块，并给出「类别新颖度 × 目标尺度」二维评测，是很自然的一个缺口。

数据集：COCO-OVD + LVIS-OVD + VisDrone
🟡 难度中

把扩散 / 流模型用到检测结果分布上

DiffusionDet（ICCV 2023）与 FlowOVD（arXiv:2606.00782）说明「把检测当作生成过程」是可行的， 但这条线近三年明显比 DETR 线冷。值得做的是：在同框架下对比集合预测与扩散去噪， 并回答一个具体问题——生成式范式在密集目标上是不是天然更强？

数据集：COCO + CrowdHuman · 算力：需要 4 卡级别
🟡 难度中

「训练-推理一致性」的统一视角

YOLOv9（梯度信息）、YOLOv10（双重标签分配）、DETRNN（查询排序）本质上都在处理同一件事： 让训练时看到的东西和推理时输出的东西一致。 把这三条路线放进同一个评价框架里（正样本分配的一致性度量）， 是一个有观点、且能写成综述的题目。

数据集：COCO · 算力：单卡 A10 即可
🔴 难度高

面向具体行业的开放词汇落地：一份可复用的评测基准

通用 OVD 的论文已经很多，但行业场景下的开放词汇评测几乎空白。 挑一个真实行业（电力巡检、港口、养殖、零售货架），构建带真实长尾类别的开放词汇基准， 并给出基线方法。数据与评测本身就是论文的贡献。

数据集：需自行采集与标注 · 算力：视数据规模而定
